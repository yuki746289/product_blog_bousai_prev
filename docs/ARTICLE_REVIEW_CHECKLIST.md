# 防災ブログ 記事レビュー・チェックリスト

更新日: 2026-09-02

記事を `READY_TO_PUBLISH` へ進める前に確認する。
本チェックリストは `docs/BOUSAI_SITE_SPEC.md` の具体的な確認項目として使用する。

**運用上、本ファイルはマスター項目一覧とし、実際の確認結果は各記事の `docs/reviews/Bxxx_CHECKLIST.md` に PASS / FAIL / TODO / N/A で記録する。**
記事作成・修正時は、本文等の変更と同じ作業内で記事別チェックリストも更新する。

## 1. 内容・情報量

- [ ] 記事の検索意図・読者の疑問に直接答えている
- [ ] 結論だけでなく、判断条件・理由・具体例がある
- [ ] 例外・注意点・誤解しやすい点を必要に応じて説明している
- [ ] 行動を伴う記事では、読者が「次に何をするか」が分かる
- [ ] 高リスク記事では「やってはいけないこと」も確認している
- [ ] 同じ章構成・説明文を他記事から機械的に使い回していない

### 本文量の目安

- [ ] 通常の解説・practical/detail記事: おおむね2,500〜3,500字
- [ ] pillar記事: おおむね3,000〜4,500字
- [ ] 高リスクdetail/practical記事: 原則3,000字以上を目安
- [ ] 目安を下回る場合、文章の水増しではなく、具体条件・例外・手順・ケース別説明等の不足がないか確認した
- [ ] 短いまま公開する場合、短くてよい理由を説明できる

※文字数は絶対条件ではない。内容の充足度を確認するための運用目安とする。

## 2. 出典・安全性

- [ ] 安全行動・避難・災害リスク等の重要主張は、公的・一次情報を優先して確認した
- [ ] 出典確認日を記録した
- [ ] 現行制度・警報体系・数値等が最新か確認した
- [ ] 公的資料が示していない安全保証や一律基準を作っていない
- [ ] 高リスク記事は目視レビュー前に公開しない

## 3. 画像・視覚要素

- [ ] 画像は記事内容を直感的に補助している
- [ ] 意味の弱い画像を枚数合わせで入れていない
- [ ] 前半だけに画像が集中していない
- [ ] 2〜3章ごとを目安に、画像・図・表・カード・チェックリスト・注意ボックス等の視覚要素を原則配置した（不要な場合は理由を説明できる）
- [ ] ヒーロー画像は原則として記事固有である
- [ ] 記事固有の説明写真・雰囲気写真を他記事から使い回していない
- [ ] 同一バッチ内で同じ写真を複数記事へ使っていない
- [ ] 公的資料等を再利用した場合、再利用する必然性と理由を画像メモへ記録した
- [ ] 画像ライセンス・出典・作者・利用条件を確認した
- [ ] 日本の住宅・道路・避難所・車・生活場面を扱う記事では、日本の実写または日本の生活文脈に合う画像を優先した
- [ ] 海外画像を使う場合、国による違いが読者の理解を妨げない汎用的な対象か確認した
- [ ] 日本の適切な実写がない場合、安全上の誤解がない範囲で日本向け図解または記事専用AI生成画像で原則補完した
- [ ] テキストだけの章が長く続いていないか確認し、画像と見せ方の両面で改善した
- [ ] 画像が0枚、または長文に対して明らかに少ない場合、安全に生成できる場面は記事専用AI生成画像で原則補完した
- [ ] 表・カード・注意ボックス等の見せ方を追加したことだけを理由に、本来必要な画像追加を省略していない
- [ ] 安全上の誤解がなく生成可能なテーマなのに、理由なく「画像なし」または画像不足のままで終わらせていない
- [ ] AI生成画像を使う場合、記事固有の場面・内容になっている
- [ ] AI生成画像を他記事へ安易に使い回していない
- [ ] 生成画像を実写・公的資料と誤認させる表示になっていない
- [ ] 生成画像の用途・配置・生成理由を画像メモへ記録した
- [ ] ハザードマップ・避難経路・危険度・浸水深・安全水深など安全判断に関わる図をAI生成していない
- [ ] 実在商品の性能証明・ニュース写真・実災害現場の代替としてAI画像を使用していない

## 4. 読みやすさ

- [ ] 長い文章が連続しすぎていない
- [ ] 画像の有無にかかわらず、表・箇条書き・カード・要点枠・注意ボックス等を記事内容に応じて原則使用している
- [ ] 重要な判断基準・数値・注意点・行動を適度に太字にしている
- [ ] 太字は原則1段落1〜2か所以内で、強調しすぎていない
- [ ] 太字だけを追っても重要ポイントが概ね把握できる
- [ ] スマートフォンで読みにくい表・画像配置になっていない

## 5. 内部リンク・商品導線

- [ ] pillar/detail/practical間の関連リンクが自然に接続されている
- [ ] 未作成ページへのリンクは公開時に404にならない
- [ ] 情報記事では商品購入を結論にしていない
- [ ] 記事内容に自然に関連する商品群がないか確認した
- [ ] 関連商品がある場合、対応する商品紹介ページへの内部リンクを掲載した、または掲載しない合理的な理由がある
- [ ] 商品を扱う場合、原則として「情報記事 → 商品紹介ページ → Amazon」の導線を使っている
- [ ] 商品リンクの位置が本文の文脈と一致している
- [ ] 高リスク記事では安全行動・公的情報より前に購買導線を置いていない
- [ ] 安全情報より広告・商品名が目立つ構成になっていない
- [ ] 掲載商品は記事本文で説明した用途・課題・想定読者に合っている
- [ ] 記事内容と関係の薄い商品を売れ筋・高評価だけを理由に掲載していない
- [ ] 商品ごとに「向く人・強み・注意点・主要仕様」を説明できる
- [ ] 安全性に関わる仕様はAmazon商品説明だけでなくメーカー公式情報等でも確認した

## 6. 公開前最終確認

- [ ] タイトルと本文内容が一致している
- [ ] 同時作成した記事同士で構成・文章・画像が過度に似ていない
- [ ] 記事台帳のステータス・出典数・画像数・レビュー日が一致している
- [ ] publish_blockers が空になっている
- [ ] 公開HTMLのリンク・画像・alt・HTML構造を確認した
- [ ] 必要なGoogle Analyticsタグが本番ページに入っている


## 7. Q&Aレビュー

Q&Aを新規作成・修正した場合は、公開前に以下を確認する。

### 7.1 疑問解決

- [ ] 質問に対する結論が最初の1〜2文で分かる
- [ ] 「契約による」「状況による」「確認してください」だけで終わっていない
- [ ] 一般的なケースでは通常どうなるかを説明している
- [ ] 読者が自分の状況へ当てはめられる判断材料がある
- [ ] 回答を読んだ後に「結局どうすればよいか」が分かる
- [ ] 例外・注意事項を先に並べて結論を曖昧にしていない

### 7.2 質問タイプ別

- [ ] Yes/No型は、「はい」「いいえ」「一般的には○○」のいずれかを冒頭で示している
- [ ] 数値型は、公的根拠のある目安が存在する場合、具体的な数字を示している
- [ ] 数値が安全基準・保証値ではない場合、その用途と限界を説明している
- [ ] 人数・日数等へ当てはめられる質問では、必要に応じて簡単な計算例を示している
- [ ] 「何をすればよいか」型は、行動を優先順に示している
- [ ] 「必要ですか？」型は、必須・有用・家庭条件次第のどれに近いかを先に示している
- [ ] 保険・制度型は、見るべき契約項目・補償項目・原因区分を具体的に示している

### 7.3 具体性

- [ ] 回答内に「一般例・具体例・数値・計算例・確認項目・行動手順」のいずれかが最低1つある
- [ ] 「確認する」と書く場合、可能な範囲で何を確認するかを具体的に書いている
- [ ] 専門家・自治体・保険会社等への相談が必要な場合も、その前に一般的な考え方を説明している
- [ ] 詳細記事を読まなくても、短い一般回答として最低限の疑問が解決する

### 7.4 安全性・出典

- [ ] 高リスク、安全行動、保険・制度、数値目安は公的・一次情報または確認済み詳細記事と整合している
- [ ] `docs/research/QA_SOURCES.md` または対応記事の出典メモで根拠を追跡できる
- [ ] 公的資料が示していない安全水準・保証値を作っていない
- [ ] 保険金支払可否や制度適用を個別ケースまで保証していない
- [ ] 試験条件の数値を実生活の安全基準として誤用していない
- [ ] リアルタイム情報が必要な質問では、最新の公的情報を優先する旨が明確

### 7.5 関連リンク・商品

- [ ] 回答末尾に適切な詳細記事リンクがある
- [ ] 作成済み記事が「準備中」のままになっていない
- [ ] 未作成記事リンクが公開時に404にならない
- [ ] 商品との関連が自然な場合のみ商品紹介ページへ接続している
- [ ] 高リスクQ&Aで商品リンクが安全情報より目立っていない
- [ ] 商品購入を安全保証のように表現していない

### 7.6 トップページ同期

- [ ] トップページ掲載Q&AとQ&A一覧の結論が一致している
- [ ] 数値・一般例・主要な例外条件が矛盾していない
- [ ] トップ版を短縮した結果、「状況による」だけの曖昧な回答へ戻っていない
- [ ] Q&A一覧を更新した際、トップ掲載5件も確認した


## 14. 強調表示・視覚的な読みやすさ

- [ ] 太字は結論、重要語、数値、条件、禁止事項を中心に使用している。
- [ ] 太字が少なすぎず、斜め読みでも要点を拾える。
- [ ] 太字・背景色を使いすぎて本文全体が強調状態になっていない。
- [ ] 背景色は、結論・注意・危険・補足の用途に応じて統一している。
- [ ] 12章以上の記事では、冒頭画像だけでなく本文内の視覚要素を2件以上原則配置した。
- [ ] 5〜7章、または約1,200字を超えて画像・表・カード・要点枠等がない区間を作っていない。
- [ ] 画像が十分にある場合でも、表・カード・強調・背景色・注意ボックス等の見せ方を記事全体で工夫している。
- [ ] 見せ方の工夫だけで本来必要な画像を代替せず、画像不足は実写・図解・安全なAI画像で別途補完した。
- [ ] 追加画像は記事固有で、出典・作者・ライセンスまたはAI生成であることを記録した。
- [ ] AI生成画像を安全基準、避難判断、補償可否、商品性能の根拠にしていない。
