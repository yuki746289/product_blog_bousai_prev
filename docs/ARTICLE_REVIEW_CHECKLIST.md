# 防災ブログ 記事レビュー・チェックリスト

更新日: 2026-09-01

記事を `READY_TO_PUBLISH` へ進める前に確認する。
本チェックリストは `docs/BOUSAI_SITE_SPEC.md` の具体的な確認項目として使用する。

## 1. 内容・情報量

- [ ] 記事の検索意図・読者の疑問に直接答えている
- [ ] 結論だけでなく、判断条件・理由・具体例がある
- [ ] 例外・注意点・誤解しやすい点を必要に応じて説明している
- [ ] 行動を伴う記事では、読者が「次に何をするか」が分かる
- [ ] 高リスク記事では「やってはいけないこと」も確認している
- [ ] 同じ章構成・説明文を他記事から機械的に使い回していない

### 本文量の目安

- [ ] 通常の解説・practical/detail記事: おおむね2,500〜3,500字
- [ ] pillar記事: おおむね3,000〜4,500字
- [ ] 高リスクdetail/practical記事: 原則3,000字以上を目安
- [ ] 目安を下回る場合、文章の水増しではなく、具体条件・例外・手順・ケース別説明等の不足がないか確認した
- [ ] 短いまま公開する場合、短くてよい理由を説明できる

※文字数は絶対条件ではない。内容の充足度を確認するための運用目安とする。

## 2. 出典・安全性

- [ ] 安全行動・避難・災害リスク等の重要主張は、公的・一次情報を優先して確認した
- [ ] 出典確認日を記録した
- [ ] 現行制度・警報体系・数値等が最新か確認した
- [ ] 公的資料が示していない安全保証や一律基準を作っていない
- [ ] 高リスク記事は目視レビュー前に公開しない

## 3. 画像・視覚要素

- [ ] 画像は記事内容を直感的に補助している
- [ ] 意味の弱い画像を枚数合わせで入れていない
- [ ] 前半だけに画像が集中していない
- [ ] 2〜3章ごとを目安に、画像・図・表・チェックリスト・注意ボックス等の視覚要素を検討した
- [ ] ヒーロー画像は原則として記事固有である
- [ ] 記事固有の説明写真・雰囲気写真を他記事から使い回していない
- [ ] 同一バッチ内で同じ写真を複数記事へ使っていない
- [ ] 公的資料等を再利用した場合、再利用する必然性と理由を画像メモへ記録した
- [ ] 画像ライセンス・出典・作者・利用条件を確認した
- [ ] 適切な写真がない場合、別画像 → 図表 → AI生成画像 → 画像なし、の順で無理のない代替を検討した
- [ ] ハザードマップ・避難経路・危険度・数値図など安全判断に関わる図をAI生成していない

## 4. 読みやすさ

- [ ] 長い文章が連続しすぎていない
- [ ] 表・箇条書き・カード等を必要に応じて使っている
- [ ] 重要な判断基準・数値・注意点・行動を適度に太字にしている
- [ ] 太字は原則1段落1〜2か所以内で、強調しすぎていない
- [ ] 太字だけを追っても重要ポイントが概ね把握できる
- [ ] スマートフォンで読みにくい表・画像配置になっていない

## 5. 内部リンク・商品導線

- [ ] pillar/detail/practical間の関連リンクが自然に接続されている
- [ ] 未作成ページへのリンクは公開時に404にならない
- [ ] 情報記事では商品購入を結論にしていない
- [ ] 記事内容に自然に関連する商品群がないか確認した
- [ ] 関連商品がある場合、対応する商品紹介ページへの内部リンクを掲載した、または掲載しない合理的な理由がある
- [ ] 商品を扱う場合、原則として「情報記事 → 商品紹介ページ → Amazon」の導線を使っている
- [ ] 商品リンクの位置が本文の文脈と一致している
- [ ] 高リスク記事では安全行動・公的情報より前に購買導線を置いていない
- [ ] 安全情報より広告・商品名が目立つ構成になっていない

## 6. 公開前最終確認

- [ ] タイトルと本文内容が一致している
- [ ] 同時作成した記事同士で構成・文章・画像が過度に似ていない
- [ ] 記事台帳のステータス・出典数・画像数・レビュー日が一致している
- [ ] publish_blockers が空になっている
- [ ] 公開HTMLのリンク・画像・alt・HTML構造を確認した
- [ ] 必要なGoogle Analyticsタグが本番ページに入っている
