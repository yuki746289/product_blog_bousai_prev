# 防災ブログ 共通記事レビュー・チェックリスト

更新日: 2026-09-03

本ファイルは `docs/CONTENT_CREATION_RULES.md` を検証する**public側作業コピー**。正本はprivateリポジトリ `yuki746289/product_blog_rules` の `sites/bousai/rules/ARTICLE_REVIEW_CHECKLIST.md`。

個別記事の `docs/reviews/Bxxx_CHECKLIST.md` へ以下の行をコピーしない。
記事別ファイルには、各セクションの判定、根拠、記事固有の追加確認だけを記録する。

判定値: `PASS / FAIL / TODO / N/A`

## C01 内容・情報量

- [ ] **C01-01** 検索意図・読者の疑問に直接答えている
- [ ] **C01-02** 結論、判断条件、理由、具体例がある
- [ ] **C01-03** 例外・注意点・誤解しやすい点を必要に応じて説明している
- [ ] **C01-04** 行動記事では次に取る行動が分かる
- [ ] **C01-05** 高リスク記事では「やってはいけないこと」を確認した
- [ ] **C01-06** 他記事の章構成・文章を機械的に使い回していない
- [ ] **C01-07** 記事役割に対して本文量・情報量が十分。目安未満なら不足がない理由を説明できる
- [ ] **C01-08** title / H1が主検索意図と一致し、他公開ページと役割が重複していない
- [ ] **C01-09** meta descriptionが存在し、本文内容を固有の文章で正確に要約している
- [ ] **C01-10** キーワード起点の記事では既存記事・Q&A・商品ページとのカニバリ確認を行った

## C02 出典・安全性

- [ ] **C02-01** 重要主張は公的・一次情報を優先した
- [ ] **C02-02** 出典確認日を記録した
- [ ] **C02-03** 制度・警報体系・数値が現行か確認した
- [ ] **C02-04** 根拠のない安全保証・一律基準を作っていない
- [ ] **C02-05** 試験値等を実生活の安全基準として誤用していない
- [ ] **C02-06** 高リスク記事の目視レビューを完了した

## C03 画像・視覚要素

- [ ] **C03-01** 各画像が配置章の内容と直接関連し、何を補助するか説明できる
- [ ] **C03-02** 枚数合わせの雰囲気写真を入れていない
- [ ] **C03-03** 日本の生活文脈が重要な記事では日本向け画像を優先した
- [ ] **C03-04** ヒーロー・記事固有画像を安易に他記事へ使い回していない
- [ ] **C03-05** ライセンス・出典・作者・利用条件を確認した
- [ ] **C03-06** AI画像を安全判断・公式図・商品性能・ニュース写真の代替にしていない
- [ ] **C03-07** AI画像を使った場合、記事固有で用途・生成理由を記録した
- [ ] **C03-08** 外部画像の実表示、404/403、ホットリンク制限を確認した
- [ ] **C03-09** 外部画像失敗時にページが崩れないフォールバックがある
- [ ] **C03-10** 商品画像を本文画像数へ加算していない

## C04 読みやすさ・UI

- [ ] **C04-01** 長い文章が連続しすぎていない
- [ ] **C04-02** 画像・表・カード・チェックリスト・注意ボックス等を適切に配置した
- [ ] **C04-03** 長い視覚要素なし区間を見直した
- [ ] **C04-04** 結論・判断基準・数値・禁止事項等を適度に太字にした
- [ ] **C04-05** 太字・背景色を使いすぎていない
- [ ] **C04-06** 章見出し・要点・注意・危険・商品CTA・Amazon CTA・Q&A CTA・関連記事・表ヘッダーが役割別に区別されている
- [ ] **C04-07** 主要UIを色だけでなく形・枠・アイコン・余白等でも判別できる
- [ ] **C04-08** 商品CTAが章見出しの色違いだけのデザインになっていない
- [ ] **C04-09** スマートフォンで表・画像・CTAが崩れていない

## C05 内部リンク

- [ ] **C05-01** pillar/detail/practicalの関連リンクが自然
- [ ] **C05-02** detail/practicalから親pillarへ戻れる
- [ ] **C05-03** 作成済みページに「準備中」・`href="#"`・plannedクラスが残っていない
- [ ] **C05-04** 未作成ページへの404リンクがない
- [ ] **C05-05** アンカーテキストで遷移先の内容が分かる

## C06 商品導線・商品記事（条件付き）

情報記事で商品と自然に関連する場合:

- [ ] **C06-01** 商品記事への導線を検討し、必要なら本文中の自然な位置に置いた
- [ ] **C06-02** 商品導線を記事末尾だけに依存していない
- [ ] **C06-03** 一般情報記事では原則「情報記事 → 商品紹介記事 → Amazon」の順
- [ ] **C06-04** 同一商品記事への過剰な重複リンクがない
- [ ] **C06-05** 高リスク記事で商品導線が安全情報より前に出ていない

具体商品を紹介する記事:

- [ ] **C06-06** 必要性・選び方の説明直後に具体商品を自然に紹介している
- [ ] **C06-07** 「商品候補」「採用理由」等の制作側表現を読者向け本文に出していない
- [ ] **C06-08** 商品カードに商品名・画像・価格情報・用途・仕様・強み・注意点・Amazonリンクがある
- [ ] **C06-09** `docs/AFFILIATE_POLICY.md` の商品選定・ASIN・価格・画像・リコール条件を満たす

## C07 Q&A（条件付き）

Q&Aを作成・更新する場合:

- [ ] **C07-01** 結論が最初の1〜2文で分かる
- [ ] **C07-02** 「状況による」「確認してください」だけで終わっていない
- [ ] **C07-03** 一般例・例外・確認ポイント・次の行動が分かる
- [ ] **C07-04** 数値・制度・安全情報は確認済み根拠と整合している
- [ ] **C07-05** 詳細記事リンクが適切

記事本文からQ&Aへ接続する場合:

- [ ] **C07-06** 直接対応する疑問がある場合、関連箇所からQ&A個別アンカーへの導線を検討した
- [ ] **C07-07** Q&Aリンクを本文説明の代替にしていない
- [ ] **C07-08** 全記事へ機械的にQ&Aリンクを追加していない
- [ ] **C07-09** 同一Q&Aへの過剰な重複リンクがない

## C08 同期・公開前

- [ ] **C08-01** Markdown / preview HTML / research memo / checklist / registryを必要範囲で同期した
- [ ] **C08-02** タイトルと本文内容が一致する
- [ ] **C08-03** 同時作成記事と文章・画像が過度に類似していない
- [ ] **C08-04** 台帳のステータス・レビュー日・出典・画像情報が一致する
- [ ] **C08-05** `publish_blockers` が空
- [ ] **C08-06** HTMLリンク・画像・alt・構造を確認した
- [ ] **C08-07** 共通UIを変更した場合は `docs/SITE_RELEASE_CHECKLIST.md` も実行した
- [ ] **C08-08** 本番ビルドでtitle / meta descriptionの欠落・完全重複チェックがPASSした

## 個別チェックリストへの記録方法

記事別ファイルでは、例として次のように記録する。

| 共通チェック | 状態 | 根拠・備考 |
|---|---|---|
| C01 内容・情報量 | PASS | 本文3,100字。判断条件・例外あり |
| C02 出典・安全性 | PASS | SOURCES.md確認 |
| C03 画像・視覚要素 | PASS | 画像3点、権利・関連性確認 |
| C04 読みやすさ・UI | PASS | スマホ目視済み |
| C05 内部リンク | PASS | 親pillar・関連detail確認 |
| C06 商品 | N/A | 商品導線不要 |
| C07 Q&A | PASS | qa-water-daysへ文脈リンク |
| C08 同期・公開前 | PASS | HTML/Markdown/registry同期 |

**共通項目の全文を記事別ファイルへ再掲しない。**


## C09 日付・構造化データ

| チェック項目 | 判定 |
|---|---|
| `published_at` が初回公開日として台帳に記録されている | PASS / FAIL / N/A |
| `modified_at` が本文の最終更新日と一致し、レビュー日を機械的に流用していない | PASS / FAIL / N/A |
| `source_checked_at` が本文根拠の最終確認日と一致する | PASS / FAIL / N/A |

| BlogPostingのheadline / datePublished / dateModifiedが台帳と一致する | PASS / FAIL / N/A |

| JSON-LDを記事HTMLへ個別に重複実装していない | PASS / FAIL / N/A |


## C10 デザイン・UX

UX/UIデザイナー視点で確認する。

- [ ] **C10-01** ページを短時間見ただけで、記事・商品・Q&A・警告・リアルタイム情報等の役割を誤認しない
- [ ] **C10-02** 最重要情報 → 補足 → 次の行動の視覚的優先順位が自然
- [ ] **C10-03** 異なる役割のUIを、同じカードデザインの色違いだけで使い回していない
- [ ] **C10-04** 新しい要素だけが背景色・影・サイズ等でサイト全体から不自然に浮いていない
- [ ] **C10-05** 逆に、役割の違う要素が既存記事と似すぎて誤認を招いていない
- [ ] **C10-06** 強い背景色・グラデーション・影・枠線を必要以上に重ねていない
- [ ] **C10-07** カード化・ボックス化した要素は、独立表示する理由を説明できる
- [ ] **C10-08** 余白・文字サイズ・揃え方・情報密度が同一階層で整っている
- [ ] **C10-09** ページ固有UIと共通UIのデザイン言語が矛盾していない
- [ ] **C10-10** PCとスマートフォンで情報の優先順位が維持される
- [ ] **C10-11** スマートフォンで単純な縦積みにした結果、見出しと内容の関係が分かりにくくなっていない
- [ ] **C10-12** 装飾を外しても情報構造が理解できる
- [ ] **C10-13** ページ全体を目視し、「目立つ」と「浮いている」を混同していない
- [ ] **C10-14** 新規UIはスクリーン全体で見たとき、前後セクションとの接続が自然

## C11 読者・マーケティング

マーケター / CRO・読者戦略の視点で確認する。

- [ ] **C11-01** target_readerを状況ベースで説明できる
- [ ] **C11-02** usage_context（どんな場面で読むか）が本文内容と一致している
- [ ] **C11-03** knowledge_levelを前提にしすぎず、初心者が必要な説明を省いていない
- [ ] **C11-04** reader_problemが冒頭・構成・結論へ反映されている
- [ ] **C11-05** reader_goalとして、読後にできるようになることを説明できる
- [ ] **C11-06** page_job（このページの役割）が1文で説明できる
- [ ] **C11-07** entry_pathと本文冒頭が噛み合っている
- [ ] **C11-08** next_actionが自然で、読者に不要な行動を強いていない
- [ ] **C11-09** 商品導線がある場合、読者が購入判断に必要な情報を得た後に置かれている
- [ ] **C11-10** 同程度に強いCTAが競合していない
- [ ] **C11-11** 商品を買わない読者にもページ単体で価値がある
- [ ] **C11-12** 年齢・性別・家族構成等の不要な決めつけでペルソナを作っていない
- [ ] **C11-13** 収益性だけを理由に、検索意図と合わない商品・記事へ誘導していない
- [ ] **C11-14** 安全行動・公的情報よりコンバージョン導線を優先していない

## C12 アクセシビリティ

アクセシビリティ / インクルーシブデザイン視点で確認する。

- [ ] **C12-01** 見出し階層が意味順になっている
- [ ] **C12-02** リンク文言だけで遷移先の内容が分かる
- [ ] **C12-03** 内容を持つ画像に適切なaltがある
- [ ] **C12-04** 重要情報を色だけで区別していない
- [ ] **C12-05** キーボードで主要リンク・ボタン・開閉UIを操作できる
- [ ] **C12-06** フォーカス位置が視覚的に確認できる
- [ ] **C12-07** 本文・注記・CTAが小さすぎない
- [ ] **C12-08** スマートフォンでタップ対象が密集しすぎていない
- [ ] **C12-09** 表・横長情報がスマートフォンでも内容を失わず読める
- [ ] **C12-10** 点滅・過剰な自動アニメーションへ重要情報を依存していない
- [ ] **C12-11** 専門用語・制度名は対象読者に応じて説明されている
- [ ] **C12-12** 安全上重要な内容を画像内文字だけで伝えていない
- [ ] **C12-13** 高齢者等を扱う場合、対象を一律に「できない人」として表現していない

## C13 技術品質・パフォーマンス・信頼性

Webエンジニア視点で確認する。

- [ ] **C13-01** ページ固有CSS/JSを共通アセットへ不要に混在させていない
- [ ] **C13-02** 同一機能を複数ファイルへ重複実装していない
- [ ] **C13-03** JavaScript構文・主要実行経路を確認した
- [ ] **C13-04** CSS/JS/画像/JSON等の主要アセットが本番HTTPで取得できる
- [ ] **C13-05** 外部画像・外部API失敗時の表示がある
- [ ] **C13-06** 外部取得失敗を「問題なし」「情報なし」と誤解させない
- [ ] **C13-07** 画像のwidth/height等により大きなレイアウトずれを抑えている
- [ ] **C13-08** ファーストビュー以外の重い画像は必要に応じて遅延読込している
- [ ] **C13-09** 不要な巨大画像・重複CSS/JS・第三者スクリプトを増やしていない
- [ ] **C13-10** 主要ページでPC/モバイル表示崩れを確認した
- [ ] **C13-11** 動的情報には情報源・最終取得時刻・失敗/遅延状態・公式導線がある
- [ ] **C13-12** 本番ビルド・自動テスト・HTTPスモークが変更範囲に応じてPASSしている
- [ ] **C13-13** Lighthouse等を使う変更では単発スコアだけでなく変更前後・主要ボトルネックを比較した
- [ ] **C13-14** 通常デプロイと定期更新等、別更新経路が互いのデータを上書きしない

## C14 計測・グロース（条件付き）

新しいCTA、GA4イベント、検索改善、トップ機能等で適用する。

- [ ] **C14-01** 変更目的を1文で説明できる
- [ ] **C14-02** 目的に対応する主指標を定めた
- [ ] **C14-03** イベントは「取得できるから」ではなく改善判断に必要だから追加している
- [ ] **C14-04** CTAクリックと購入・問題解決を同一視していない
- [ ] **C14-05** GA4イベント名・パラメータが既存命名と整合している
- [ ] **C14-06** 不要な個人情報・入力値を分析イベントへ送っていない
- [ ] **C14-07** Search Consoleで評価する場合、クエリ・表示回数・CTR・順位を分けて見る
- [ ] **C14-08** 公開後に想定と異なる場合、title・内容・導線・UIを分けて原因分析できる
- [ ] **C14-09** 数値改善のために安全性・アクセシビリティ・検索意図を損なっていない

## 専門家視点の最終横断チェック

- [ ] **X01** 誰の、どんな困りごとを解決するページか一文で説明できる
- [ ] **X02** 最初に何が重要だと伝わるか説明できる
- [ ] **X03** 読後に何をすればよいか説明できる
- [ ] **X04** SEO・収益・デザイン上の都合が安全性を上回っていない
