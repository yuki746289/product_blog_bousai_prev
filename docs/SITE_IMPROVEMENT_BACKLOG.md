# サイト改善・対応事項

更新日: 2026-09-03

Geminiレビュー、現サイト監査、運用上の改善点を統合した対応事項。
一般論をそのまま採用せず、現サイトとの差分だけを管理する。

判定:
- `TODO`: 対応候補
- `PLANNED`: 方針確定・実施待ち
- `WAITING_DATA`: データ蓄積後に実施
- `DONE`: 対応済み
- `REJECTED`: 現仕様では採用しない

| 優先 | 対応事項 | 状態 | 方針 |
|---|---|---|---|
| A | キーワード調査を記事企画の標準工程へ追加 | DONE | `docs/KEYWORD_RESEARCH_POLICY.md` を正本とする |
| A | ラッコキーワード等で不足テーマ・具体的疑問を定期抽出 | PLANNED | 1キーワード1記事にせず検索意図でクラスタリング |
| A | 公開日・最終更新日の明示 | TODO | 公開日・最終更新日・情報確認日の役割を整理 |
| A | Article/BlogPosting等の構造化データ | TODO | FAQPageリッチリザルト目的ではなく記事情報の明確化を目的とする |
| A | 外部画像依存の縮小・WebP等の最適化 | TODO | ライセンス確認後、再配布可能な画像から順次ローカル化 |
| A | モバイル実機レビュー | TODO | 現行の横スクロールナビ、Q&A、表、商品CTAを確認 |
| B | 商品記事へ数量・容量・稼働時間等の概算例を追加 | TODO | 条件・損失・例外を明記し保証表現にしない |
| B | 出典リンクの表示名を統一 | TODO | 生URL表示を減らし「機関名『資料名』」形式へ |
| B | 季節前のリライト・記事公開サイクル | PLANNED | 需要ピークの1〜2か月前に確認 |
| C | ペット・乳幼児・高齢者等の属性別テーマ調査 | PLANNED | キーワード需要と既存記事との差を確認してから記事化 |
| C | 困りごと・ネガティブ検索語の調査 | PLANNED | 「重すぎる」「いらない」「捨てる」等を問題解決型テーマとして評価 |
| 後日 | Search Consoleデータ駆動リライト | WAITING_DATA | 表示回数・CTR・順位データが蓄積してから開始 |
| - | FAQPageリッチリザルト獲得目的の実装 | REJECTED | Googleの現行検索仕様では優先施策にしない |

## キーワード調査の運用

次の記事群を追加する前に、原則として一度キーワード調査を行う。

```text
ラッコキーワード等
  ↓
検索意図でクラスタリング
  ↓
既存30記事・Q&A・商品記事と照合
  ↓
既存記事強化 / 新規記事 / Q&A / 商品導線 / 見送り
  ↓
pillar/detail構造へ配置
  ↓
公開後はSearch Consoleで検証
```

詳細は `docs/KEYWORD_RESEARCH_POLICY.md` を参照する。
