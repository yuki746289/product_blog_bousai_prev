# 防災ブログ 専門家視点レビュー・フレームワーク

更新日: 2026-09-04

## 1. 位置づけ

本ファイルは、防災サイト「防災くらしガイド」で実際に使う専門家レビューの運用索引である。

上位の共通ルール:
- `docs/COMMON_SITE_REVIEW_FRAMEWORK.md`

防災サイトの適用判定:
- `docs/BOUSAI_SITE_REVIEW_PROFILE.md`

チェックリスト:
- 共通記事レビュー: `docs/ARTICLE_REVIEW_CHECKLIST.md`
- 防災サイト固有: `docs/BOUSAI_SITE_REVIEW_CHECKLIST.md`
- 共通UI変更: `docs/SITE_RELEASE_CHECKLIST.md`

記事作成ルール:
- `docs/CONTENT_CREATION_RULES.md`

このファイルはルール本文を重複管理するためではなく、各専門家視点がどのルール・チェックを担当するかを整理するために使う。

## 3. ペルソナ運用

防災サイトの `persona_mode` は `SITUATIONAL_SEGMENT`。

詳細な架空人物像は作らない。

必須:
- target_reader
- usage_context
- knowledge_level
- urgency_level（必要な場合）
- reader_problem
- reader_goal
- page_job
- entry_path
- next_action
- conversion_path
- design_priority

年齢・年収・職業・家族構成等は、記事内容に実際の差が出る場合に限り状況・制約として使用する。

例:
- 乳幼児がいる家庭
- 高齢者本人・支援者
- ペット飼育世帯
- 車利用者
- マンション居住者
- 停電中
- 避難所へ移動する人

## 4. E01 編集者 / コンテンツストラテジスト

目的:
- 読者が迷わず理解できる
- 必要十分な情報量
- 他記事の使い回しではない
- ページの役割が一貫している

主な作成ルール:
- CR-01
- CR-04
- CR-05
- CR-07

主なレビュー:
- C01
- C04
- C05
- C07

## 5. E02 防災・ファクトチェック / リスクレビュー

目的:
- 誤った安全判断を誘発しない
- 数値・制度・製品仕様を断定しすぎない
- 公的・一次情報と自サイト解説を分離する

主な作成ルール:
- CR-02
- CR-08A
- CR-10
- 各専門方針

主なレビュー:
- C02
- C09
- S08

高リスク記事では最優先。

## 6. E03 SEO / 検索戦略

目的:
- 検索者の疑問へ正しく答える
- 既存ページと競合しない
- 検索エンジンにもページ役割が伝わる

主な作成ルール:
- CR-01B
- CR-05
- CR-09A
- CR-11
- `docs/KEYWORD_RESEARCH_POLICY.md`

主なレビュー:
- C01-08〜C01-10
- C05
- C08-08
- C09

SEOは安全性・正確性より下位。

## 7. E04 情報設計 / ファインダビリティ

目的:
- 欲しい情報へ迷わず到達できる
- カテゴリ、パンくず、URL、ラベルが整合する
- 情報記事、商品記事、Q&A等の役割をサイト構造上も区別する

主なレビュー:
- C05
- S02

重点:
- カテゴリ構造
- パンくず
- ナビゲーション
- URLとページ役割
- 関連記事・Q&A・商品導線
- 孤立ページ防止

- 役割、優先順位、視線誘導、レイアウトが直感的

目的:
- 高齢者、スマートフォン利用者、キーボード利用者等を含め、重要情報へ到達できる

主な作成ルール:

- 不安を煽ってクリック・購入を促さない
- 用語・CTA・説明トーンを統一する
- 公的情報と自サイト解説を誤認させない

主なレビュー:
- C04
- C10

- アフィリエイトであることと公的推奨を混同させない

- 海外制度や海外製品仕様を日本の一般基準として扱わない
- 地域差・自治体差を全国一律と断定しない

主なレビュー:
- C03
- C11
- S05

- 個別修正だけでなく再発防止へつなげる
- 通常デプロイとリアルタイム更新等の複数経路を安全に共存させる

## 19. 専門家視点の優先順位

1. 人命・安全・重大な誤判断の防止
2. 正確性・公的根拠・情報鮮度
3. アクセシビリティ
4. 法務・権利・プライバシー
5. 読者理解・UX・情報設計
6. 日本の制度・生活文脈への適合
7. 技術的信頼性・運用保守性
8. SEO・ブランド
9. 収益・CV・グロース

## 20. 最終レビュー原則

個別チェックをPASSした後、最後に次を確認する。

1. 誰の、どんな困りごとを解決するページか
2. 最初に何が重要だと伝わるか
3. 読後に何をすればよいか
4. 公的情報・安全情報と自サイト解説・商品導線を誤認しないか
5. 日本の利用状況に合っているか
6. 適用すべき専門家視点に未判定がないか
7. 公開後の更新責任・鮮度確認方法が明確か

この7点が不明瞭なら、個別チェックがPASSでも公開前に再設計する。
