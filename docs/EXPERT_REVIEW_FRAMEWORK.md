# 防災ブログ 専門家視点レビュー・フレームワーク

更新日: 2026-09-03

## 1. 目的

記事やページを「文章として正しいか」だけでなく、複数の専門家視点から作成・レビューする。

このフレームワークは新しいルールを別系統で重複管理するためのものではない。
各専門家視点が、どの作成ルールとチェックリストを担当するかを整理する索引として使う。

正本:
- 作成ルール: `docs/CONTENT_CREATION_RULES.md`
- 共通レビュー: `docs/ARTICLE_REVIEW_CHECKLIST.md`
- 共通UI変更: `docs/SITE_RELEASE_CHECKLIST.md`

## 2. 専門家視点

| ID | 専門家視点 | 主な問い | 適用 |
|---|---|---|---|
| E01 | 編集者 / コンテンツストラテジスト | 読者が理解しやすく、独自の構成で、必要十分に答えているか | 全ページ |
| E02 | 防災・ファクトチェック / リスクレビュー | 安全行動・数値・制度・出典が正確で、誤解を招かないか | 全記事。高リスクは必須強化 |
| E03 | SEO / 検索戦略 | 検索意図、カニバリ、title、内部構造が適切か | 検索流入を狙う公開ページ |
| E04 | UX / UIデザイナー | 役割、優先順位、視線誘導、レイアウトが直感的か | 全公開ページ |
| E05 | マーケター / CRO・読者戦略 | 誰のどの課題に応え、読後に何をしてほしいか明確か | 全公開ページ |
| E06 | アクセシビリティ / インクルーシブデザイン | 年齢・端末・操作方法にかかわらず重要情報へ到達できるか | 全公開ページ |
| E07 | Webエンジニア / パフォーマンス・信頼性 | 壊れず、速く、適切に配信され、失敗時も安全か | 全公開ページ・共通実装 |
| E08 | 商品編集 / アフィリエイト・購買支援 | 商品紹介が読者の購入判断を助け、誤認・押し売りになっていないか | 商品記事・商品導線のみ |
| E09 | アナリスト / グロース | 目的に対応する計測があり、公開後の改善判断ができるか | 主要導線・新機能・収益導線 |

## 3. コア視点と条件付き視点

### コア7視点

E01〜E07は原則として全公開ページへ適用する。

ただし全項目を毎回同じ深さで実施するのではなく、変更範囲に合わせる。

例:
- 文章だけの修正: E01/E02/E03/E05を中心に確認
- CSS変更: E04/E06/E07を強く確認
- トップページ新機能: E04/E05/E06/E07/E09を強く確認
- 高リスク防災記事: E02を最優先

### 条件付き2視点

E08:
- 商品記事
- Amazonリンク
- 商品画像
- 商品比較
- 情報記事から商品記事への導線

がある場合のみ適用する。

E09:
- 新しいCTA
- GA4イベント
- ファネル変更
- トップページの新機能
- 検索・収益改善を目的とした変更

の場合に適用する。

## 4. 視点ごとの作成ルールとチェック先

### E01 編集者 / コンテンツストラテジスト

目的:
- 読者が迷わず理解できる
- 必要十分な情報量
- 他記事の使い回しではない
- ページの役割が一貫している

作成ルール:
- CR-01 内容・オリジナリティ
- CR-04 読みやすさ・強調・UI
- CR-05 内部リンク
- CR-07 Q&A

レビュー:
- C01
- C04
- C05
- C07

重点確認:
- 結論が早い
- 構成がテーマに合っている
- 説明不足と水増しの両方を避ける
- 同じ章立てを別記事へ機械的に流用しない
- 読後に「何が分かったか」が一文で言える

### E02 防災・ファクトチェック / リスクレビュー

目的:
- 防災情報として誤った安全判断を誘発しない
- 数値・制度・製品仕様を断定しすぎない

作成ルール:
- CR-02 出典・安全性
- CR-08A 日付
- CR-10 情報鮮度
- 高リスク時は各専門方針

レビュー:
- C02
- C09
- 高リスク記事の追加安全レビュー

優先順位:
1. 人命・安全
2. 公的・一次情報
3. 読みやすさ
4. SEO
5. 収益

SEOや収益上有利でも、安全性と矛盾する表現は採用しない。

### E03 SEO / 検索戦略

目的:
- 検索者の疑問へ正しく答える
- 既存ページと競合しない
- 検索エンジンにもページ役割が伝わる

作成ルール:
- CR-01B title・meta description・検索意図
- CR-05 内部リンク
- CR-09A 構造化データ
- CR-11 キーワード調査・記事企画
- `docs/KEYWORD_RESEARCH_POLICY.md`

レビュー:
- C01-08〜C01-10
- C05
- C08-08
- C09

検索順位だけでなく、検索者が欲しい答えとページ役割の一致を優先する。

### E04 UX / UIデザイナー

目的:
- 3秒程度見ただけでページ内の役割と優先順位が分かる
- 記事、商品、警告、リアルタイム情報等を誤認しない
- サイト全体にはなじみつつ、必要な役割差は明確

作成ルール:
- CR-03 画像・視覚要素
- CR-04 読みやすさ・UI
- CR-12 デザイン・UX品質

レビュー:
- C03
- C04
- C10 デザイン・UX

デザインは「目立つか」ではなく、
- 理解できるか
- 誤認しないか
- 視線が自然か
- サイト全体で調和するか

で評価する。

### E05 マーケター / CRO・読者戦略

目的:
- 誰向けのページかを明確にする
- 読者の現在地から次の行動まで設計する
- 収益導線を読者価値の結果として置く

作成ルール:
- CR-05 内部リンク
- CR-06 商品紹介
- CR-11 記事企画
- CR-13 読者・マーケティング設計

レビュー:
- C05
- C06
- C11 読者・マーケティング

「詳細な架空人物」を毎記事作るのではなく、
- 対象読者
- 利用状況
- 知識レベル
- 困りごと
- 読後ゴール
- 次の行動

を定義する。

### E06 アクセシビリティ / インクルーシブデザイン

目的:
- 高齢者、スマートフォン利用者、キーボード利用者等を含め、重要情報を取得できる
- 色・画像・細かい文字だけに意味を依存しない

作成ルール:
- CR-14 アクセシビリティ・利用しやすさ

レビュー:
- C12 アクセシビリティ

防災サイトでは、アクセシビリティは装飾品質ではなく安全性の一部として扱う。

### E07 Webエンジニア / パフォーマンス・信頼性

目的:
- リンク・画像・CSS・JSが壊れない
- ページ固有処理を共通コードへ不要に混在させない
- 遅延・外部サービス失敗時にも誤情報を出さない

作成ルール:
- CR-08 同期・記録
- CR-09 公開前・共通UI変更
- CR-15 技術品質・パフォーマンス・信頼性

レビュー:
- C08
- C09
- C13 技術品質
- `docs/SITE_RELEASE_CHECKLIST.md`

### E08 商品編集 / アフィリエイト・購買支援

条件付き。

目的:
- 読者が「買う / 買わない」を判断できる
- 商品を安全行動の代替にしない
- 型番・画像・仕様・価格表現を誤認させない

作成ルール:
- CR-05B
- CR-06
- `docs/AFFILIATE_POLICY.md`

レビュー:
- C06
- 商品記事条件付きレビュー

### E09 アナリスト / グロース

条件付き。

目的:
- 変更目的に対応した指標がある
- 計測だけを増やさず、改善判断へつなげる

作成ルール:
- CR-16 計測・グロース設計

レビュー:
- C14 計測・グロース

主な対象:
- Search Console
- GA4
- `product_guide_click`
- `amazon_click`
- 主要CTA
- 新規トップ機能

## 5. 専門家視点の優先順位

視点が衝突した場合は次の順で判断する。

1. 安全性・正確性
2. アクセシビリティ
3. 読者理解・UX
4. 読者課題・ページ目的
5. 技術的信頼性
6. SEO
7. 収益・コンバージョン

例:
- SEO上クリックされやすい強い断定でも、安全根拠が弱ければ使わない
- 商品CTAのCTRが高くても、安全説明より先に置かない
- デザイン上きれいでも、重要情報が小さすぎれば採用しない

## 7. 最終レビュー原則

公開前の最終確認では「各チェックがPASSしたか」だけで終わらせない。

最後にページ全体を見て、次の3問へ答える。

1. **誰の、どんな困りごとを解決するページか**
2. **最初に何が重要だと伝わるか**
3. **読後に何をすればよいか**

この3つが不明瞭なら、個別チェックがPASSでも公開前に再設計する。
