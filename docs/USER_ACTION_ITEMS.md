## 4. 優先度

現在の優先度は次のとおり。

1. サイト改善・記事作成はChatGPT側で継続する。
2. U10は商品ページの信頼性に直結するため、早めに確認する。API資格情報はリポジトリや公開JavaScriptへ保存しない。
3. U04〜U07はデータ蓄積待ちのため、現時点で無理に実施しない。U07はCI除外反映後のデータのみを主対象にする。
4. U08は任意。公開SERP、Search Console、既存キーワード調査等で判断可能な場合は必須にしない。

## 5. U10 Amazon品切れ対策の方針

### 5.1 優先方式

Amazon公式の現行商品APIで在庫状態を取得できる場合は、そのAPIを使う。Amazon商品ページのHTMLをスクレイピングして在庫判定する方式は採用しない。

在庫監視で区別する状態:

- 在庫あり
- 在庫僅少
- 入荷待ち・将来入荷予定
- 品切れ
- 利用不可・販売終了相当
- 状態不明

### 5.2 APIを利用できる場合

- Amazon Associates CentralでCreators APIの利用可否を確認する。
- 認証情報はGitHub Actions Secrets等の非公開領域でのみ管理する。
- 定期処理で掲載ASINの在庫状態を確認する。
- `OUTOFSTOCK` や `UNAVAILABLE` を検出しても、無関係な別商品へ自動差し替えしない。
- 既存の選定条件を満たす代替候補を抽出し、人間または記事レビュー工程で確認してから差し替える。
- 状態取得自体に失敗した場合は「在庫あり」と扱わない。

### 5.3 APIを利用できない間

- 商品カードを単一商品依存にしすぎず、用途ごとに複数候補を維持する。
- 長期欠品・終売を確認した商品は、同じ用途の確認済み商品へ差し替える。
- 適切な代替商品を即時確定できない場合は、商品名・型番を固定したAmazon検索リンク、または用途カテゴリの検索リンクへ一時的に切り替える。
- 「Amazonで在庫・価格を確認」等、リンク先で最新状態を確認することが分かる文言を維持する。
- 品切れを確認した日、差し替え日、旧ASIN、新ASINまたは代替リンクを商品メモに残す。

## 6. フィードバック後の扱い

ユーザー確認で問題が見つかった場合は、ChatGPT側で以下を行う。

- 原因切り分け
- リポジトリ修正
- 必要なら共通ルール・チェックリスト更新
- 自動テスト化可能な問題は回帰テスト追加
- 本番反映・スモーク確認

単発修正だけで終わらせず、再発防止まで検討する。
