# 共通サイト作成・レビュー・フレームワーク

更新日: 2026-09-04

## 1. 目的

本ファイルは、特定サイトに依存しない**共通の専門家視点・適用判定ルール**のpublic側作業コピーとする。正本はprivateリポジトリ `yuki746289/product_blog_rules` で管理する。

新しいサイトを作るときに、必要な観点をゼロから思い出す方式にしない。まず本ファイルの専門家視点をすべて検討し、サイト個別プロファイルで `REQUIRED / CONDITIONAL / N/A` を明示する。

重要:

- 共通ルールにあるからといって、すべてのサイトで全項目を必須にはしない。
- 不要な観点を削除しない。`N/A` と理由を記録する。
- `CONDITIONAL` は、適用条件と対象ページ種別を記録する。
- サイト固有の事情は共通ルールを書き換えず、サイト個別プロファイルで上書きする。
- ページ単位で例外を作る場合も、理由と適用範囲を記録する。

## 2. 継承構造

```text
共通サイト作成・レビューフレームワーク
  ↓
サイト個別プロファイル
  ↓
ページ種別ルール
  ↓
個別ページ / 記事固有条件
```

優先順位は下位の具体的設定を優先する。ただし、安全性、法令、権利、アクセシビリティ等の上位制約を、ページ都合だけで弱めてはならない。

## 3. 適用ステータス

| 状態 | 意味 |
|---|---|
| `REQUIRED` | 原則として対象範囲で必須。省略時は理由と承認が必要 |
| `CONDITIONAL` | 条件に該当する場合のみ必須。条件をサイトプロファイルへ記載 |
| `N/A` | 現在のサイトでは対象外。理由を必ず記載 |

サイトプロファイルで未判定の専門家視点を残してはならない。

## 4. 共通専門家カタログ

### P01 編集者 / コンテンツストラテジスト

主な責務:
- 内容の必要十分性
- 論理構成
- 独自性
- 読みやすさ
- 記事・ページの役割一貫性

主な問い:
- 読者の疑問へ直接答えているか
- 説明不足、水増し、使い回しがないか
- 結論、判断条件、例外、次の行動が整理されているか

### P02 ドメイン専門家 / 安全・業務レビュー

主な責務:
- 分野固有の正確性
- 実務上の安全性
- 禁止事項・例外
- 誤解による損害防止

医療、金融、法律、防災、食品、製品安全、技術等、誤りの影響が大きいサイトでは強化する。

### P03 リサーチャー / ファクトチェック・エビデンス品質

主な責務:
- 一次情報、公的情報、原典の優先
- 出典の妥当性
- 情報鮮度
- 事実と推測の分離
- 数値の条件・母集団・測定方法の確認

### P04 SEO / 検索戦略

主な責務:
- 検索意図
- title / H1 / meta description
- カニバリ
- 内部リンク
- インデックス設計
- 構造化データ

SEO上有利でも、読者価値や安全性を損なう施策は採用しない。

### P05 情報アーキテクト / タクソノミー・ファインダビリティ

主な責務:
- カテゴリ構造
- ナビゲーション
- パンくず
- ラベル
- URL体系
- サイト内で情報を見つけやすい構造

### P06 UX / UIデザイナー

主な責務:
- 情報階層
- 視線誘導
- レイアウト
- 誤認防止
- PC / スマートフォンの利用性
- デザインの一貫性

「目立つ」と「分かりやすい」を混同しない。

### P07 アクセシビリティ / インクルーシブデザイン

主な責務:
- 見出し構造
- キーボード操作
- フォーカス
- alt
- 色依存回避
- 文字・タップ対象
- 支援技術や高齢者等を含む利用しやすさ

### P08 顧客調査 / ペルソナ・セグメンテーション

主な責務:
- 誰が利用するか
- どの状況で利用するか
- 知識レベル
- 課題、動機、障壁
- セグメント差

#### ペルソナ運用

詳細ペルソナは全サイト共通の必須項目ではない。サイト個別プロファイルで次のいずれかを選ぶ。

| persona_mode | 用途 |
|---|---|
| `NONE` | 読者区分が内容にほぼ影響しない特殊ケース |
| `SITUATIONAL_SEGMENT` | 状況・制約・目的ベースで読者を定義する |
| `EVIDENCE_BASED_PERSONA` | 調査・購買データ等に基づき詳細ペルソナを作る |
| `HYBRID` | 状況セグメントと根拠のあるペルソナを併用する |

詳細ペルソナを使う場合も、架空の名前・年齢・年収・家族構成等を埋めること自体を目的にしない。コンテンツ、商品、導線、トーン、判断基準を実際に変える属性だけを採用する。

### P09 マーケター / カスタマージャーニー・CRO・サービスデザイン

主な責務:
- reader problem / goal
- entry path
- page job

- 離脱・迷い・購買障壁

### P10 ブランドストラテジスト / コンテンツデザイナー

- 用語統一

- 読者との距離感
- ページ種別をまたいだ表現一貫性

### P11 商品編集 / EC・アフィリエイト・マーチャンダイジング

主な責務:
- 商品選定
- 比較軸
- 仕様・画像・価格表現
- 購入判断支援
- 広告・アフィリエイトの透明性
- 売り込み過多の防止

### P12 アナリスト / 実験・グロース

主な責務:
- KPI
- GA / Search Console等の計測
- 仮説検証
- A/Bテスト
- 改善効果の判定
- 相関と因果の混同防止

### P13 Webエンジニア / パフォーマンス・信頼性

主な責務:
- HTML / CSS / JavaScript
- レスポンシブ実装
- 外部API・画像
- エラー時挙動
- キャッシュ
- パフォーマンス
- デプロイ・回帰テスト

### P14 セキュリティ / プライバシー・データ保護

主な責務:
- 入力値・認証・権限
- 個人情報
- Cookie / 計測
- 外部スクリプト
- 秘密情報
- ログ
- 不要なデータ収集の防止

認証や入力フォームがなくても、第三者スクリプトや計測を使う場合は完全な `N/A` と決めつけない。

### P15 法務 / コンプライアンス・権利・広告表示

主な責務:
- 著作権・ライセンス
- 商標
- プライバシーポリシー
- 広告・アフィリエイト表示
- 業法・表示規制
- 免責表現
- 利用規約

法的判断が必要な場合は、専門家確認が必要な領域と編集上判断できる領域を分離する。

### P16 ローカライゼーション / 文化・地域文脈

主な責務:
- 国・地域の制度差
- 生活文脈
- 単位・日付・言語
- 画像の文化適合
- 地域固有の慣行
- 翻訳では失われる意味

### P17 コミュニティ / UGC・モデレーション

主な責務:
- 投稿ルール
- 通報
- 荒らし・スパム
- 誤情報
- 個人情報
- 権利侵害
- コミュニティ健全性

UGC、コメント、レビュー、掲示板等がなければ `N/A` にできる。

### P18 運用設計 / ガバナンス・保守性

主な責務:
- 正本の明確化
- 更新責任
- レビュー周期
- 変更履歴
- チェックリスト
- 再発防止
- 複数更新経路の整合
- 属人化防止

### P19 配信戦略 / SNS・PR・ディストリビューション

主な責務:
- 検索以外の流入
- SNSシェア
- OGP
- 投稿文脈
- プレス・外部露出
- 再訪導線

検索中心でSNS運用を行わないサイトは `N/A` または `CONDITIONAL` にできる。

### P20 事業 / 収益モデル・マネタイズ

主な責務:
- 収益構造
- 広告・課金・アフィリエイトの位置づけ
- 読者価値との整合
- 収益導線の副作用
- 継続運用可能性

### P21 データ / 統計・可視化レビュー

主な責務:
- 集計方法
- 分母・母集団
- 欠損
- 外れ値
- 時系列比較
- グラフ表現
- 推計と実測の区別
- 不確実性表示

数値・ランキング・統計・予測を扱うサイトで適用する。

### P22 カスタマーサポート / サービス運用

主な責務:
- 問い合わせ導線
- ヘルプ / FAQ
- 障害時案内
- 解約・返品・予約変更等の利用者手続き
- サポート負荷

サービス提供・会員機能・予約・購入後支援等がない純粋な情報サイトでは `N/A` にできる。

## 5. サイト個別プロファイルの必須項目

新規サイトでは最低限、以下を作成する。

```yaml
site_review_profile:
  site_purpose:
  primary_audience:
  primary_conversion:
  risk_level:
  persona_mode:
  expert_applicability:
    P01: REQUIRED | CONDITIONAL | N/A
    ...
    P22: REQUIRED | CONDITIONAL | N/A
```

各 `CONDITIONAL / N/A` には理由を付ける。

## 6. ページ種別への適用

サイトプロファイル確定後、少なくとも次の単位で必要なチェックを分ける。

- トップページ
- カテゴリ / 一覧
- 情報記事
- 商品 / LP
- Q&A / FAQ
- 固定ページ
- 動的 / リアルタイム機能
- 会員 / 入力フォーム（存在する場合）
- UGC / コメント（存在する場合）

すべてのページへ同じチェックリストを機械的に適用しない。

## 7. ルール追加・削除の原則

1. 2件以上のページで同じ問題が再発した場合、サイト共通または全サイト共通への昇格を検討する。
2. サイト固有事情を全サイト共通へ安易に昇格しない。
3. `N/A` にした項目でも、サイト機能追加により条件が変わった場合は再評価する。
4. 共通項目を削除するより、適用プロファイルで除外する。
5. チェックリストは「検討した証跡」を残すため、不要項目にも理由を残す。

## 8. 優先順位

専門家視点が衝突した場合の共通原則:

1. 人命・安全・重大な損害回避
2. 法令・権利・プライバシー
3. 正確性・エビデンス
4. アクセシビリティ
5. 読者理解・UX
6. ページ目的・情報設計
7. 技術的信頼性
8. ブランド・検索・配信
9. 収益・CV

サイト固有のリスクに応じて、より厳しい優先順位を追加してよい。
