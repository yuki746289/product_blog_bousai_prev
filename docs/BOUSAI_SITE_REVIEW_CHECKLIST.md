# 防災くらしガイド サイト個別レビュー・チェックリスト

更新日: 2026-09-04

## 1. 位置づけ

本ファイルは、防災サイト固有の追加チェックと、既存共通チェック `docs/ARTICLE_REVIEW_CHECKLIST.md` の適用設定を管理する。

参照順:

1. `docs/COMMON_SITE_REVIEW_FRAMEWORK.md`
2. `docs/BOUSAI_SITE_REVIEW_PROFILE.md`
3. `docs/CONTENT_CREATION_RULES.md`
4. `docs/ARTICLE_REVIEW_CHECKLIST.md`
5. 本ファイル
6. ページ種別・記事固有チェック

判定値:

- `PASS`
- `FAIL`
- `TODO`
- `N/A`

`N/A` には理由を残す。

## 3. S01 サイトプロファイル・適用判定

- [ ] **S01-01** `docs/BOUSAI_SITE_REVIEW_PROFILE.md` の適用判定を確認した
- [ ] **S01-02** ページ種別に必要な専門家ロールを選んだ
- [ ] **S01-03** `CONDITIONAL` の条件に該当する視点を漏らしていない
- [ ] **S01-04** `N/A` を無言で省略せず、サイトプロファイルの理由と整合している
- [ ] **S01-05** 詳細架空ペルソナを作成していない
- [ ] **S01-06** `target_reader / usage_context / reader_problem / reader_goal / page_job / next_action` を最低限説明できる
- [ ] **S01-07** 高リスクページでは収益・SEO・デザイン都合より安全レビューを優先した

## 4. S02 情報設計・ファインダビリティ

情報アーキテクト視点。

- [ ] **S02-01** ページの所属カテゴリが内容と一致する
- [ ] **S02-02** パンくずが実際のサイト階層と一致する
- [ ] **S02-03** グローバルナビ・カテゴリ導線のラベルだけで行き先を理解できる
- [ ] **S02-04** 同一内容への複数名称が無秩序に混在していない
- [ ] **S02-05** URL・カテゴリ・title・H1・パンくずの役割が矛盾していない
- [ ] **S02-06** 関連記事・商品・Q&Aへの導線が、サイト構造上自然な位置にある
- [ ] **S02-07** 新規ページを孤立させていない
- [ ] **S02-08** カテゴリ一覧で情報記事・商品記事等のページ種別を誤認しない
- [ ] **S02-09** 「詳しく」「こちら」等だけの曖昧ラベルへ戻していない

## 5. S03 法務・権利・広告表示・プライバシー

法務 / 権利 / プライバシー視点。

- [ ] **S03-01** 使用画像・図表・引用の権利条件を確認した
- [ ] **S03-02** Wikimedia Commons等は作者・ライセンス・出典を保持している
- [ ] **S03-03** 商品画像は利用条件に反する取得・転載をしていない
- [ ] **S03-04** Amazon等のアフィリエイト導線はサイト方針と表示上整合している
- [ ] **S03-05** 広告・商品紹介を公的推奨・安全保証のように見せていない
- [ ] **S03-06** GA4等へ不要な個人情報・入力値を送っていない
- [ ] **S03-07** secret・パスワード・APIキー等をHTML・リポジトリ・本文へ露出していない
- [ ] **S03-08** 外部資料の引用は必要最小限で、出典と自サイト本文を混同しない
- [ ] **S03-09** 法的断定が必要な内容を、根拠なく自サイト判断で断定していない

## 6. S04 ブランド・トーン・コンテンツデザイン

ブランド / コンテンツデザイン視点。

- [ ] **S04-01** 防災サイトとして落ち着き・信頼性を損なう煽り表現を使っていない
- [ ] **S04-02** 不安を過度に刺激してクリックや購入を促していない
- [ ] **S04-03** 商品ページでも販売色が安全情報・読者価値を上回っていない
- [ ] **S04-04** 用語・見出し・CTA文言がサイト内で一貫している
- [ ] **S04-05** 制作側の内部用語を読者向け本文へ出していない
- [ ] **S04-06** 新規UI・文章だけがサイト全体から不自然に浮いていない
- [ ] **S04-07** 公的情報と自サイト解説の見た目・文言を区別できる
- [ ] **S04-08** 「おすすめ」「安心」「安全」等の強い語を根拠なく使っていない

## 7. S05 日本向けローカライゼーション・生活文脈

ローカライゼーション視点。

- [ ] **S05-01** 日本の制度・警報体系・自治体運用と整合している
- [ ] **S05-02** 海外制度・海外製品仕様を日本の一般基準として扱っていない
- [ ] **S05-03** 住宅・道路・避難所・車・生活場面の画像は日本文脈を優先している
- [ ] **S05-04** 海外画像を使う場合、理解を妨げる文化・制度差がない
- [ ] **S05-05** 単位、日付、数量表現が日本の読者に自然
- [ ] **S05-06** 自治体差・地域差がある内容を全国一律と断定していない
- [ ] **S05-07** 高齢者、乳幼児、ペット、障害、居住形態等を固定的なステレオタイプで表現していない

## 8. S06 運用・ガバナンス・保守性

運用設計視点。

- [ ] **S06-01** 正本ファイルが明確で、同じルールを複数ファイルへ重複記載していない
- [ ] **S06-02** 記事・HTML・台帳・research・checklist等の必要ファイルを同期した
- [ ] **S06-03** `published_at / modified_at / source_checked_at / last_reviewed_at` の意味を混同していない
- [ ] **S06-04** 情報鮮度ポリシーに沿って次回確認対象を管理している
- [ ] **S06-05** 共通問題を個別ページだけで直さず、再発防止ルール・テスト化を検討した
- [ ] **S06-06** 通常デプロイとリアルタイム更新等の複数経路が互いの成果物を上書きしない
- [ ] **S06-07** CI・ビルド・スモーク等、変更範囲に応じた検証結果を確認した
- [ ] **S06-08** 一時的な手修正だけで本番と正本が乖離していない
- [ ] **S06-09** 新機能追加時に、現在 `N/A` の専門家視点を再評価した

## 9. S07 セキュリティ・外部依存

セキュリティ / 信頼性視点。

- [ ] **S07-01** 外部JavaScript・外部API・外部画像を必要以上に増やしていない
- [ ] **S07-02** 外部取得失敗時に、安全上誤った既定値を表示しない
- [ ] **S07-03** リアルタイム情報で「取得失敗」と「情報なし」を区別する
- [ ] **S07-04** 外部リンクの `_blank` は `noopener` 等の既存方針に従う
- [ ] **S07-05** リポジトリ・ログ・公開HTMLへ認証情報を出していない
- [ ] **S07-06** GA4等の計測を追加した場合、送信項目を確認した
- [ ] **S07-07** 今後フォーム・認証・UGCを追加する場合、P14/P17/P22を再評価する

## 10. S08 数値・統計・リアルタイム要約（条件付き）

数値比較、ランキング、集計、予測、リアルタイム情報を扱う場合。

- [ ] **S08-01** 数値の分母・単位・期間・条件が明確
- [ ] **S08-02** 推計値・説明用仮定・実測値・製品公称値を区別している
- [ ] **S08-03** 平均・割合・順位等の集計方法を誤解させない
- [ ] **S08-04** 欠損・取得失敗をゼロとして扱っていない
- [ ] **S08-05** 単一の数値を安全保証や一律基準に変換していない
- [ ] **S08-06** グラフ・表を使う場合、視覚上の誇張や不適切な比較がない

## 13. 最終横断判定

既存X01〜X05に加え、防災サイトでは次も確認する。

- [ ] **SX01** 適用すべき専門家視点に未判定がない
- [ ] **SX02** `N/A` は「忘れた」のではなく、サイトプロファイル上の理由がある
- [ ] **SX03** 詳細ペルソナを作らなくても、誰がどの状況で読むページか明確
- [ ] **SX04** 公的情報・安全行動と、自サイト解説・商品導線を誤認しない
- [ ] **SX05** 日本の読者が実際に使う状況・制度・生活文脈と合っている
- [ ] **SX06** 公開後に誰が・いつ・何を再確認するか不明な状態で終わっていない
- [ ] **SX07** 個別修正で終わらせず、再発しそうな問題はルール・テスト化を検討した

## 14. 運用原則

- 共通ルールは広く保持する。
- 防災サイトで不要なものはサイトプロファイルで `N/A` にする。
- ページ固有の都合だけで共通安全ルールを外さない。
- サイト機能が変わったら、まず適用プロファイルを再評価してからチェック項目を追加する。
- チェックリストを増やすこと自体を目的にせず、重複するチェックは既存項目へ統合する。
